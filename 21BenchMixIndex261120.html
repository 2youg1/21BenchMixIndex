趋势

以编程能力外推

但就过去一年和未来可能半年到一年的趋势来看，以编程能力为绝对核心来衡量模型的总体实力，或者说以编程能力来外推模型在科研，机器人，或者常见办公领域的能力，具有相当大的解释力。

当你在选择模型的时候，这个指数结合你对模型体感的加权可以作为模型的性能分，然后按照订阅实际可用额度和厂家补贴额度算出成本，就可以计算性价比以衡量模型是否符合你的需求了。

WHY

为什么做一个指数

我之前在 Bilibili 更新了不少国模模型评测视频，但现在我一边不断完善个人的开发工作流（并将其直接编入 GitHub 仓库之后）， 我在测试用的大型仓库中的经验突然让我想到：我对模型的评价高度拟合 Artificial Analysis Coding Agent Benchmarks （即 FrontierCode-AA 2.0 + Terminal-Bench 4.1 + SWE-Atlas-QnA-AA 三者的平均数）结合 VALS 的榜单的一种复杂变体。

但榜太多就导致了很多模型没成绩，以及很难调基于 VCB 和 PB 加权惩罚系数。如果没有 CursorBench 就提高 FrontierCode / Terminal-Bench 4.1 / FrontierSWE 各自 10% / 5% / 5%，没有 ProgramBench 就按最近地底分拟合。

AA Intelligence Index v5.0.1 的区分度不够，这个新的参数以更高的区分度（如果差别不够高就用当前最高分放大为 1 然后算相对分）、为优质指标或符合真实任务的 Benchmark 赋予更多的影响因子，来更直观地区分能把事情做对（Right）的分高模型， 把事情做完（Work）的一般模型，和无法完成任务的差模型。

缺测处理 transparent imputation

CB 缺失：不插补。把 CB 的 0.20 权重按 FC +0.10、TB +0.05、FSWE +0.05 回退，重新配平到 1.00。表内显示为“回退”。

PB 缺失：按最近地底分拟合。优先同族低阶实测；没有同族锚点时取同级邻近值或该项最低实测。

VCB100 / FSWE 缺失：同族优先，其次按能力邻近模型拟合。每个建议值都带来源，可在抽屉里直接改。

状态标记：无前缀 = 实测；≈ = 拟合；回退 = CB 缺失触发公式回退；— = 按 0 计。

AA 对照 same-anchor scaling

AA Intelligence Index v5.0.1 是 0–100 的综合智能分，权重与这里不同。它不是“正确答案”，而是一个独立的参照系。

在 Fable = 1 模式下，AA 也除以 Fable 的 AA 分；在 最高 = 1 模式下，AA 除以候选池最高 AA 分；在 原始分 模式下，AA 直接除以 100。缺口 = MIX − AA，单位是 pt。

缺口为正，说明这个模型在长任务 / 乘数项上比 AA 的综合智能排序更占优；缺口为负，说明它的综合智能分高于混合指数给出的位置。

口径与限制 caveats

跨 harness：AA Coding Agent 用 agent harness，CursorBench 用模型 effort 档，VALS 用 OpenHands。它们不是同一实验条件下的对照。

单点分数：公开榜大多只给均值，没有置信区间。一次 0.5 分的差距，可能落在噪声里。

拟合不确定性：琥珀色数字是估计值，不是实测值。把关键决策压在拟合值上之前，先用你自己的任务做小样本对照。

Benchmark notes

Benchmark 指南

如何使用这个指数

COST

成本参考模型

C = [ C_token + C_human ] · (1 + r_retry + r_rework) · A_agent / S_plan

C_token = Σ_stages [ N_in · p_in_eff + N_out · p_out ] · k(t)
p_in_eff = (1 − h) · p_in + h · p_hit
N_out = N_base · ε
C_human = w · ( N_out / TPS + t_review + t_rework_comm )
01
stages

探索 + 制作 + 验收，分开算：有时你有完整计划，有时你人工验收，各阶段的 token 结构完全不同。

02
p_in_eff

缓存唯一的位置：只作用在输入侧。h 越高 p_in_eff 越贴近 p_hit，但 p_hit 不为零，所以命中率的边际收益必然递减。

03
N_out

ε = Token 效率 = 该模型输出 token ÷ 基准模型输出 token。思考 token 计入输出，max 模式下 ε 会被人为吹大。

04
k(t)

峰谷系数，越来越多的国产模型出现高峰 k=2 的情况，有些达到了 K=5，按实际调用时段加权。你不是吸血鬼或者迭代了超时工作的话，工作时间大概率会覆盖满主流高峰期（有高峰期设计的至少包含了 UTC+8 9:00～12:00、14:00～18:00，有时更长）。

05
C_human

w 你的时薪/精力单价；N_out/TPS 等待时间：与 ε 正相关、与 TPS 负相关——啰嗦又慢的模型在这里被双重惩罚。

06
r_retry

重试率：与 q 互为表里，重试一次 token 重算一遍，有时不止一次。

07
r_rework

返工率：返工一次连人力一起重来，比重试更贵。

08
A_agent

多 Agent 放大：每多一个 Agent 约为主 Agent 全周期成本的 1.5–2.5（无上限）倍，取决于编排能力，有时导致整个重做。

09
S_plan

Plan 补贴：边际成本趋零，但要扣机会成本（占用额度 + 上下文锁 272K 这类限制造成的返工，计回 r_rework）。
